# 打印中心 UI 改版开发说明

日期：2026-09-14

状态：方案 A 已确认并实施。

开发分支：`codex/print-center-style`

分支基线：`ab3c232`（从 `codex/chinese-copybook-ui-refresh` 创建）

## 1. 目标与结论

本次只调整打印中心首页的信息层级和视觉样式，继续复用现有语文、数学、英语打印入口、专项工具、打印历史和 PDF 能力，不扩展题型，不调整 PDF 内页模板。

推荐采用用户倾向的 **方案 A：不在打印首页展示“最近打印”**。

主要理由：

- 打印首页的核心任务是快速选择打印场景，方案 A 能保持入口清晰，三科同步打印和专项工具在常见屏幕内更完整地出现。
- 当前已经有独立“打印历史”入口与历史页，方案 A 不会丢失查找和重打能力。
- 当前打印页没有首屏数据请求；采用 A 可保持静态入口页，避免为两条最近记录新增登录、网络、空状态、过期记录和删除后的同步处理。
- “打印历史”未来仍是 Sprint 3 的必要链路；方案 A 只是避免首页重复展示历史摘要，不是移除历史。
- 页面底部使用小墨插画可以强化品牌，但不会与真实记录争夺首屏空间。

方案 B 可作为数据验证后的升级项：当真实埋点表明用户频繁从打印首页重打最近资料，或“打印历史”入口点击后立即打开前两条的比例较高，再增加最近打印模块更合理。

## 2. 设计输入与使用边界

视觉参考：[打印中心 UI 方案 A/B](../ui/source/打印中心UI方案AB-2026-09-14.png)。

附图是视觉方案，不是可直接执行的产品需求。按现有实现和正式 V2 文档校准如下：

- 图外的“方案 A / 方案 B”标题及解释是评审标注，不属于小程序页面。
- “同步教材 · 一键生成 · A4直接打印”建议改为“同步教材 · 一键生成 · 下载 PDF 后打印”，避免暗示小程序能直连打印机。
- 英语入口不使用尚未实现的“连词成句”，建议写成“字母字帖 · 单词字帖 · 默写帖”。
- “测试小卷”当前仍是后续能力，保留入口但需显示“后续开放”或等价状态，不能让视觉稿造成已经可用的误解。
- 专项训练、错题巩固、数学自由组卷等正式 V2 范围仍按 Sprint 任务书分期实现；本轮不因效果图出现而提前新增。
- 图中的打印内容缩略图只是氛围元素，不代表 PDF 内页模板；PDF 版式继续等待成熟参考。
- 视觉继续使用原版小墨和当前蓝色、浅色学科卡片体系，不混入已放弃的高年级备选视觉。

## 3. 方案 A 与 B 评估

| 维度 | 方案 A：无最近打印 | 方案 B：显示最近打印 |
| --- | --- | --- |
| 核心任务聚焦 | 最好，首屏全部服务于“开始打印” | 较好，生成入口与历史入口并存 |
| 页面长度 | 较短，常见机型更容易看到完整工具区 | 较长，小屏需继续滚动 |
| 重复打印效率 | 需点击“打印历史”多一步 | 最近两条可直接打开 |
| 首屏数据依赖 | 无，静态渲染即可 | 需加载云端历史并处理本地兜底 |
| 状态复杂度 | 低 | 中，需加载、空、失败、过期、删除同步 |
| 当前复用程度 | 最高 | 可复用历史页逻辑，但会形成重复代码或需抽公共层 |
| 品牌展示 | 可保留完整页尾小墨 | 空间有限，页尾插画需移除或缩小 |
| 当前建议 | **采用** | 保留为后续数据驱动升级 |

若未来采用 B，应抽取共享的历史摘要转换逻辑，且最多显示 2 条；首页失败时静默隐藏，不阻塞打印入口。

## 4. 推荐页面结构

页面沿用微信原生导航栏标题“打印”，正文按以下顺序排列：

1. Hero：标题“打印中心”、一句准确副标题、三条能力说明，以及“小墨 + 打印机 + 练习册”插画。
2. 同步教材：语文、数学、英语三张纵向入口卡片。
3. 专项工具：偏旁部首、名字字帖、测试小卷、打印历史四宫格。
4. 页尾品牌卡：小墨抱铅笔与书本；只在方案 A 展示。

不再保留当前页正文顶部独立的“打印资料”标题与旧暖橙 PDF Hero，避免与新 Hero 重复。

### 4.1 Hero 建议文案

## 5. 视觉与交互规范

- 页面背景跟随当前首页的 `#f3f7fc`，主文字沿用深蓝，学科色继续使用语文红、数学蓝、英语绿。
- Hero 背景渐变、标题、说明、勾选图标和手写字均由 WXML/WXSS 绘制；只把复杂插画作为透明 PNG。
- 学科卡的“语 / 数 / ABC”采用文字与渐变底色绘制，不切成图片，以便适配屏幕和大字体。
- 卡片保持整行可点击，点击热区不小于约 44×44 CSS px；按下态需有透明度或轻微缩放反馈。
- 右箭头使用统一矢量/CSS 方案；不把箭头烘焙进卡片图。
- 方案 A 的页尾品牌卡应自然结束页面，不能为了铺满屏幕强制拉伸；小屏允许正常滚动。
- “后续开放”不仅依赖灰色，应同时有明确文字标签；无障碍标签应说明对应入口与状态。
- 不把效果图中 iPhone 状态栏、微信胶囊、导航栏、底部 TabBar 或页面圆角手机外框做进切图。

## 6. 数据与代码影响

方案 A 不需要新增接口、数据库或持久化结构。

确认实施后预计只修改：

- `miniprogram/pages/print/print.wxml`
- `miniprogram/pages/print/print.wxss`
- `miniprogram/pages/print/print.js`：仅在补充可访问性或状态文案时轻量调整；现有导航动作保持。
- `miniprogram/assets/print/*`：新增经确认的打印页插画和专项工具图标。

默认不修改：

- 三科学科配置页及其提交参数。
- `miniprogram/pages/history/*` 的数据与交互。
- 后端 `/sheets` 接口、文件持久化和 10 天保留逻辑。
- PDF 排版、渲染和下载链路。
- `app.json` 的底部导航结构。

## 7. 实施顺序

1. 收到并验收独立透明切图，确认像素尺寸、透明边缘和内容安全区。
2. 重构打印页 Hero、学科入口和专项工具布局，保持所有现有跳转事件不变。
3. 接入页尾品牌卡；按实际机型检查是否与 TabBar、安全区冲突。
4. 校准文案与真实功能，尤其是英语题型、测试小卷状态和“下载后打印”。
5. 在微信开发者工具和真机检查小屏滚动、大字体、点击态与图片清晰度。
6. 回归三科入口、偏旁部首、名字字帖、测试小卷提示和打印历史。

## 8. 验收标准

- 页面采用方案 A，首页不请求或展示最近打印数据。
- 三科和四个专项工具的入口行为与改版前一致。
- 测试小卷明确为未开放，不新增未定义功能。
- 不出现“直连打印机”暗示；用户能理解需先生成/下载 PDF。
- 设计稿中的系统栏、导航栏、TabBar、文字和背景没有被烘焙进业务切图。
- 插画在常见 2×/3× 屏幕清晰，无白边、黑边、毛边或明显压缩噪点。
- iPhone 小屏、常见 Android、刘海屏和系统大字体下不遮挡、不截断。
- 控制台无新增错误，页面首屏不因素材加载失败而无法操作。

## 9. 后续升级到方案 B 的触发条件

满足任一项再评估 B：

- 数据显示“打印历史”是打印页的高频入口，且多数用户打开的是最近 1–2 条。
- 用户访谈持续反馈重打路径过长。
- 打印历史支持“打开原卷 / 同配置换题”后，最近记录具备更高复用价值。

届时需额外设计最近记录的加载、空状态、过期、失败、删除同步、账号与本地兜底逻辑，不能只把两张静态卡片贴到页面。

## 10. 新增资源体积约束（2026-09-14）

- 小程序主包必须小于 1.5 MB（1,500,000 bytes）。
- 任一图片或音频运行时资源不得超过 200 KB（200,000 bytes）。
- 提交前运行 `node scripts/check-miniprogram-size.js`；超限时直接失败。
- 本约束针对 `miniprogram/` 上传内容；`docs/v2/ui/source/` 内的设计源图不进入小程序主包。
- 优先通过合理像素尺寸、WebP 和代码绘制控制体积，不以明显破坏清晰度为代价做过度压缩。

## 11. 实施记录（2026-09-14）

- 打印中心采用方案 A：Hero → 三科同步打印 → 四个专项工具 → 页尾小墨，不在首页加载最近打印。
- 三科学科入口、偏旁部首、名字字帖、测试小卷提示和打印历史沿用原有事件与页面。
- “测试小卷”明确标记为后续开放；英语文案使用当前已实现的字母字帖、单词字帖、默写帖。
- 从用户提供的素材总览提取两张小墨插画与四个专项工具图标；最初使用透明 WebP，但 iOS 预览版未显示，已全部改为透明 PNG。
- 参考语文字帖 UI 改版的浅蓝页面、学科色、轻卡片、按需设置和原版小墨使用方式，没有改变 PDF 内页模板。
- 为满足主包限制，优化首页横幅和三科学科图标的像素尺寸；文件路径不变，页面引用无需改动。
- 进一步将语文字帖的完成态、书写态小墨优化至约 129 KB 和 101 KB，降低微信上传检测的边界风险，视觉构图与透明通道保持不变。
- 新增体积检查脚本；实现后原始文件合计低于 1.5 MB，所有图片均低于 200 KB。
